# Hellar AI — Cosmic Edition

**Устанавливаемая локальная бета 0.8.0.** Единый проект: React-интерфейс, Fastify API, SQLite, приватное файловое хранилище. Регистрация по приглашениям, личный кабинет, потоковый текстовый чат и image-студия.

Проект не опубликован. Существующие Workers, домены, DNS, Hellar AI и Hellar Voice AI не изменялись. Платёжных функций нет. В архиве нет секретов, пользовательской БД, сессий или node_modules.

## Быстрый запуск

Требуется **Node.js 24 LTS** и npm. Python 3 нужен только для создания контрольных ZIP, Docker не обязателен.

```sh
npm ci
cp .env.example .env
npm run migrate
npm run admin:create
npm run dev
```

В Windows вместо `cp` можно скопировать `.env.example` в `.env` через проводник или PowerShell `Copy-Item .env.example .env`.

Открой **http://localhost:5173**. Все команды запускай из корня `hellar-cosmic`.

`admin:create` запросит email, отображаемое имя и пароль дважды в интерактивном терминале. Пароль не отображается, не передаётся аргументом команды и не хранится открытым текстом. Команда откажется создавать второго администратора. В публичной регистрации выбор роли отсутствует.

1. Войди под созданным администратором.
2. Открой **Мой кабинет → Управление доступом** (`/admin`).
3. Создай приглашение, выбрав подпись и срок.
4. Скопируй код сразу: повторно сервер его не показывает, хранится только хеш.
5. Передай код человеку лично. Он регистрируется на `/register`.

Приглашение одноразовое. Потерянный код можно отозвать и создать новый. Логи и архивы для передачи не должны содержать коды приглашений.

## Что работает без внешних ключей

Работают приглашения, регистрация, вход, сессии, административные функции, профиль, аватар, настройки, смена пароля, управление диалогами и приватными данными. Чат и студия показывают понятное сообщение, если API не настроен. Фиктивных ответов ИИ нет.

Восстановление пароля реализовано на сервере. Без SMTP отправка письма явно недоступна; восстановительные токены не выводятся в консоль или ответы API.

## Подключение реального ИИ

Используется официальный `openai` SDK на сервере. Текст — Chat Completions streaming, изображения — Images API. Реальные запросы в ходе разработки **не выполнялись: API-ключ отсутствовал**. SDK и HTTP-форматы проверены тестовым транспортом.

Секрет `OPENAI_API_KEY` задаётся только локально в `.env` либо через секреты хостинга. Не помещай его в `VITE_*`, клиентский JavaScript, Git, переписку или скриншоты. При использовании доступного безопасного подключения OpenAI ключ можно передать через защищённый процесс настройки; создание ключа и расходы требуют отдельного решения владельца.

После настройки перезапусти API. Конфигурация по умолчанию:

| Параметр                                           | Значение                      |
| -------------------------------------------------- | ----------------------------- |
| CHAT_MODELS                                        | gpt-4.1-mini                  |
| IMAGE_MODEL                                        | gpt-image-1                   |
| IMAGE_SIZES                                        | 1024x1024,1024x1536,1536x1024 |
| MAX_OUTPUT_TOKENS                                  | 1500                          |
| MAX_CONTEXT_CHARS                                  | 48000                         |
| CHAT_DAILY_LIMIT / IMAGE_DAILY_LIMIT               | 100 / 10 на пользователя      |
| GLOBAL_CHAT_DAILY_LIMIT / GLOBAL_IMAGE_DAILY_LIMIT | 1000 / 100 на весь сервис     |

Модели выбираются сервером, доступность в конкретном аккаунте проверяется живым запросом после настройки. Обработчик изображений рассчитан на GPT Image-совместимые модели с base64 PNG, `quality: low`, `n: 1`; DALL·E с URL-ответами не является взаимозаменяемым адаптером.

В стандартной конфигурации доступны **1:1, 2:3, 3:2**. Кнопки 9:16 и 16:9 проверяют точное соотношение поддерживаемых размеров и предлагают доступную альтернативу. Изображения не растягиваются и не обрезаются тайно. Добавлять точный размер в IMAGE_SIZES можно только когда выбранная модель реально его поддерживает.

## Почта

В `.env` настрой SMTP_HOST, SMTP_PORT, SMTP_SECURE, MAIL_FROM и, если провайдер требует, SMTP_USER/SMTP_PASSWORD. Порт 587 с STARTTLS — default; для 465 обычно нужен SMTP_SECURE=true. Непосредственная SMTP-отправка выполняется только при явном запросе восстановления пользователем.

APP_ORIGIN используется для ссылок восстановления и CSRF. В локальном запуске это `http://localhost:5173`; если открываешь приложение под другим адресом/портом, укажи точный origin без завершающего `/` и перезапусти backend. Не заменяй это значением `*`.

## Команды

| Команда                                    | Назначение                                         |
| ------------------------------------------ | -------------------------------------------------- |
| npm run dev                                | Vite и Fastify одновременно                        |
| npm run build                              | TypeScript, production frontend и сервер           |
| npm start                                  | Скомпилированный сервер; NODE_ENV определяет режим |
| npm test                                   | 22 изолированных автоматических теста              |
| npm run migrate                            | Применить миграции при разработке                  |
| npm run admin:create                       | Создать первого администратора при разработке      |
| npm run migrate:prod                       | Миграции после сборки без tsx                      |
| npm run admin:create:prod                  | Администратор после сборки без tsx                 |
| npm run format                             | Форматирование исходников                          |
| python3 scripts/checkpoint.py 8 "Описание" | Контрольный архив без секретов и данных            |

В production один Fastify-процесс обслуживает `/api/*` и собранный frontend из `dist/`; Vite в production не запускается. При NODE_ENV=production обязательны HTTPS APP_ORIGIN и COOKIE_SECURE=true. См. [план размещения](docs/DEPLOYMENT.md).
