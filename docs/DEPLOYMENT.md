# План последующего размещения

Ни один шаг публикации из этого документа не выполнялся. Нужен отдельный выбор хостинга и разрешение владельца.

## Первый рабочий сервер

Подходит Node.js 24-хост с persistent disk. Требуется один процесс, ориентировочно от 1 ГБ RAM для небольшого закрытого теста; объём хранилища зависит от изображений. Не использовать эфемерную файловую систему/serverless без изменения DB/storage-адаптеров.

1. Выделить отдельный каталог/контейнер и тестовый адрес для Cosmic Edition. Не перезаписывать действующие сервисы.
2. Перенести исходники, выполнить `npm ci`, `npm run build`. Проверить `npm test` до удаления devDependencies.
3. В защищённой серверной конфигурации задать NODE_ENV=production, APP_ORIGIN=https://выбранный-домен, COOKIE_SECURE=true. Настроить DATABASE_PATH/STORAGE_PATH на persistent volume. Секреты OpenAI/SMTP — только через env/secret manager.
4. Выполнить `npm run migrate:prod`, затем в интерактивном терминале `npm run admin:create:prod`.
5. Запустить `npm start` под непривилегированным пользователем с автоматическим рестартом и ограничением ресурсов. По умолчанию порт 3001 и bind 127.0.0.1.
6. Разместить HTTPS reverse proxy перед Fastify. Все запросы frontend/API идут на один origin. Для SSE отключить buffering, не применять преобразование потока, выставить read timeout более AI_TIMEOUT_MS и IMAGE_TIMEOUT_MS. Ограничить upload size 2 МБ с небольшим запасом multipart.
7. Только если приложение изолировано за доверенным proxy, включить TRUST_PROXY=true для корректных IP rate limits. Иначе оставить false; все пользователи за proxy будут делить IP-лимит.
8. Проверить регистрацию, logout, восстановление, приватные файлы, поток и остановку на настоящем HTTPS-адресе. Выполнить один текстовый и один image-запрос с разрешённым владельцем расходом.
9. Проверить Android с экранной клавиатурой и скачиванием PNG. Начать с небольшой группы приглашённых пользователей.

Нельзя запускать несколько workers/cluster/реплик поверх текущей SQLite-конфигурации.

## Docker-вариант

Dockerfile подготовлен, runtime-контейнер в этой среде не запускался.

```sh
docker build -t hellar-cosmic .
docker run -d --name hellar-cosmic --restart unless-stopped \
  --env-file .env.production \
  -p 127.0.0.1:3001:3001 \
  -v hellar-data:/app/data \
  hellar-cosmic
docker exec -it hellar-cosmic node dist-server/server/admin.js
```

В `.env.production` указать настоящий HTTPS APP_ORIGIN и секреты; сам файл не включать в образ и Git. Контейнер bind 0.0.0.0 внутри, опубликованный порт в примере доступен только локальному reverse proxy. Volume обязателен. Проверь свободное место, владельца volume и устойчивость перезапуска до приглашения пользователей.

## Обновление

Остановить процесс, сделать согласованную резервную копию, заменить код и зависимости, выполнить build/migrate, запустить один экземпляр, проверить health и основные сценарии. Миграции применяются по имени и не откатываются автоматически. Не редактировать уже применённый SQL-файл: добавлять следующий.

## Резервные копии

Для простого согласованного бэкапа остановить приложение и скопировать весь каталог `data` (включая SQLite/WAL/SHM, если есть) вместе с используемой версией migrations. Для online-backup использовать SQLite backup API и согласованную процедуру копирования файлов, не просто копировать один `.sqlite` во время записи. Хранить секреты отдельно. Проверять восстановление на изолированном экземпляре.

Удаление аккаунта не стирает его данные из старого бэкапа. Определить срок хранения и процедуру очистки резервных копий до эксплуатации.
