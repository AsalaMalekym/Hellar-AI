# Баланс, СБП и подписка Hellar

## Что реализовано

- Подписка: **$12 за календарный месяц**, покупается вручную с баланса. Включено 12 кредитов розничного расхода, то есть до **$6 себестоимости API** при наценке ×2. Автопродления и автоматических банковских списаний нет.
- 1 кредит = $1 стоимости услуг Hellar. Это внутренняя единица учёта, не криптовалюта. Оплата через Robokassa производится в рублях.
- Вначале расходуется месячный пакет, затем купленный баланс. Месячный остаток истекает; купленный остаток не сгорает. Действующие дневные и глобальные ограничения запросов сохраняются.
- Списание за фактические входные, кешированные и выходные токены из ответа OpenAI. Учитывается переданная история диалога. До вызова резервируется консервативная сумма на контекст и максимальный ответ. После завершения лишний резерв возвращается в исходный источник.
- Неопределённый расход при обрыве или перезапуске сохраняется как резерв на сверку. Следующий платный запрос этого пользователя блокируется до сверки. Администратор видит такие операции на `/billing`, ID запроса OpenAI (если получен), дату и пользователя. После сверки с провайдером можно указать реальную себестоимость либо 0 для полного освобождения резерва.
- Если реальная стоимость превысила резерв, с клиента списывается не больше резерва; превышение видно администратору как `COST_OVERRUN`. Необъяснённые превышения требуют проверки тарифов/модели, расходы сверх резерва несёт владелец.
- Перевод на SuccessURL НЕ подтверждает оплату. Зачисление — только по подписанному ResultURL, с проверкой суммы, заказа, магазина и случайного идентификатора. Повторы не начисляют средства второй раз.
- Тестовые платежи никогда не создают расходуемые кредиты. Создание тестовой оплаты доступно только администратору.
- Журнал денег не удаляется вместе с профилем. Аккаунты с остатком, действующей подпиской, незавершёнными платежами или резервами сначала закрываются через владельца.

**По умолчанию биллинг выключен (тестовую оплату может проверять администратор без включения списаний):** выкладка кода не включает платный доступ и не начинает приём денег. Реальные платежи и работа реального OpenAI-ключа не проверялись; все автоматические проверки используют заглушки.

## Подключение Robokassa для самозанятого

1. Создать и активировать магазин на https://robokassa.com/, указать фактический публичный адрес Hellar, подключить СБП. Условия оказания собственных услуг, сведения об исполнителе и контакты для возвратов нужно разместить до модерации магазина; эти персональные данные в репозитории не заданы.
2. В Robokassa подключить решение **«Самозанятые ФНС»** и подтвердить его в «Мой налог». Проверить реальный чек при запуске. Интеграция передаёт email и позицию «Предоплата услуг Hellar AI» в `Receipt`. Сам код не подтверждает подключение фискализации; совместимость этой позиции с настройками магазина проверяется в кабинете Robokassa.
3. В технических настройках магазина установить алгоритм подписи **SHA256** и отдельные пароли #1/#2 для тестового и боевого режимов. Не использовать одинаковые пароли в тестовом и боевом режиме.
4. Указать адреса, заменив `https://ВАШ-ДОМЕН` на **тот же origin, что APP_ORIGIN**:

| Поле | URL | Метод |
| --- | --- | --- |
| ResultURL | `https://ВАШ-ДОМЕН/api/payments/robokassa/result` | POST |
| SuccessURL | `https://ВАШ-ДОМЕН/billing` | GET |
| FailURL | `https://ВАШ-ДОМЕН/billing` | GET |

Серверный ResultURL должен быть доступен без Cloudflare Access/страничной капчи. Проверка Turnstile для обычных пользователей сохраняется; только этот точный POST-обработчик использует подпись Robokassa вместо пользовательской сессии и CSRF. GET на него не зачисляет деньги.

## GitHub Actions Secrets

https://github.com/AsalaMalekym/Hellar-AI/settings/secrets/actions

Не отправлять ключи в чат, не записывать их в исходники. Все настройки ниже установит существующий шаг `Install application secrets if supplied`. Секреты не передаются тестам или сборщику фронтенда.

| Имя | Значение |
| --- | --- |
| `BILLING_ENABLED` | `true` для включения учёта; `false` для отключения |
| `BILLING_RUB_PER_USD` | По согласованию с владельцем курс по умолчанию **100 ₽/$** (подписка 1200 ₽). Необязательный секрет переопределяет его; до двух знаков после точки. Это фиксированный курс сервиса, а не автоматически обновляемая биржевая котировка. |
| `ROBOKASSA_MERCHANT_LOGIN` | Логин магазина |
| `ROBOKASSA_TEST` | Сначала `true`, после проверки `false` |
| `ROBOKASSA_TEST_PASSWORD_1` | Тестовый пароль #1 |
| `ROBOKASSA_TEST_PASSWORD_2` | Тестовый пароль #2 |
| `ROBOKASSA_PASSWORD_1` | Боевой пароль #1 |
| `ROBOKASSA_PASSWORD_2` | Боевой пароль #2 |
| `BILLING_PRICES_JSON` | Подтверждённые тарифы API, USD за 1 млн токенов. Обязательно для включения реальной оплаты через workflow. |
| `OPENAI_API_KEY` | Уже используемый ключ проекта OpenAI |

Форма тарифов (пример исторических тарифов существующих моделей, **не подтверждение их текущей доступности**):

```json
{"gpt-4.1-mini":{"input":0.4,"cached":0.1,"output":1.6},"gpt-image-2.5-flare":{"input":5,"cached":1.25,"output":30}}
```

На 22.11.2026 отключённая `gpt-image-1` заменена на `gpt-image-2.5-flare`. Для генерации по тексту используются Standard-тарифы $5 за 1M входных текстовых токенов, $1.25 за кешированный вход и $30 за 1M выходных токенов изображения; клиентская наценка остаётся ×2. Доступ конкретного OpenAI-проекта к модели нужно проверить реальной генерацией после деплоя. Перед реальными продажами выбрать доступные аккаунту модели, проверить тарифы и совместимость с Chat Completions / Images API. `CHAT_MODELS` / `IMAGE_MODEL` в `wrangler.jsonc` и ключи JSON тарифов должны совпадать. Модель без тарифа блокируется до платного вызова. Этот биллинг поддерживает только текстовые чаты и генерацию изображений по тексту; аудио, инструменты, изображения на входе и тарифы длинного контекста требуют отдельной доработки. Тарифы не обновляются автоматически.

Рублёвая стоимость подписки = 12 × выбранный курс. Курс фиксируется в заказе при создании ссылки; его последующее изменение не меняет уже созданный заказ или количество купленных кредитов. Минимум пополнения 100 ₽, максимум 50 000 ₽. Комиссии, конвертация, налоги и хостинг оплачиваются из выручки; наценка ×2 не гарантирует чистую прибыль.

## Порядок запуска

1. Добавить тестовые настройки и `ROBOKASSA_TEST=true`; `BILLING_ENABLED` оставить `false` (либо не задавать); запустить **Deploy Hellar to Cloudflare → Run workflow → main**.
2. Войти администратором, открыть `/billing`, создать тестовый платёж через СБП. Он должен стать `Тест завершён — без зачисления`. Проверить ResultURL и формат чека в кабинете Robokassa. Обычным пользователям тестовая оплата закрыта. При `BILLING_ENABLED=false` чат продолжает работать без списаний и требования баланса; подписку купить нельзя.
3. После активации магазина, проверки доступных моделей/тарифов и чеков установить боевые пароли, `BILLING_PRICES_JSON`, `ROBOKASSA_TEST=false` и `BILLING_ENABLED=true`, снова выполнить workflow. Подтвердить первый реальный платёж и чек вручную. Код не совершает тестовые покупки за реальные деньги автоматически.
4. Проверить пополнение, покупку подписки, расход токенов и историю операций. Секреты по-прежнему хранятся только на сервере.

Платёжные возвраты через API Robokassa и автоматический отзыв кредитов при возврате/чарджбэке **не реализованы**. До возврата владелец должен остановить доступ соответствующего пользователя, сверить оплаченный заказ, остаток и расходы; затем вернуть деньги и скорректировать кредитный журнал контролируемой операцией. Не отменять чек без согласованного денежного возврата. Не удалять заказы/журнал вручную и не засчитывать оплату по скриншоту.

## Проверки разработчика

`npm test`, `npm run build:cloudflare`, `npm run test:cloudflare`, `npx wrangler deploy --dry-run`.

Проверяются повтор/подделка callback, несовпадение суммы, тестовые платежи, изоляция пользователей, права администратора, конкурирующие резервы, истечение пакета, отсутствие usage, восстановление после перезапуска, точное списание кешированных токенов. Cloudflare-тест использует настоящий Worker и SQLite Durable Object, заглушки OpenAI/Turnstile/Resend и callback Robokassa без cookies/CSRF. Реальные платёжные сервисы не вызываются.

## Текущие согласованные параметры

Для теста используется origin `https://hellar-ai-cosmic.woen2017.workers.dev` и фиксированный курс 100 ₽/$; подписка отображается как 1200 ₽/месяц.

- ResultURL: `https://hellar-ai-cosmic.woen2017.workers.dev/api/payments/robokassa/result` — POST.
- SuccessURL и FailURL: `https://hellar-ai-cosmic.woen2017.workers.dev/billing` — GET.

Данные технического магазина берутся из GitHub Secrets. Тестовая оплата не начисляет кредиты, не списывает реальные деньги и не включает платный доступ.


## Счётчики запросов

`/api/billing` возвращает общие и раздельные счётчики текста/картинок по подтверждённым списаниям `billing_holds`. Купленный баланс — за всё время; подписка — только её текущий период. Ошибки без списания, резервы, операции на проверке и бесплатные генерации не увеличивают использованное. Запрос со списанием из двух источников учитывается в каждом источнике, но один раз в общем числе. Счётчики не зависят от удаления переписки или лимита истории операций в интерфейсе.

Остаток — оценка в обычных текстовых запросах (1000 входных + 1000 выходных токенов без кеша, первая настроенная чат-модель). При тарифах GPT-4.1 mini ×2 и курсе 100 ₽/$: 100 ₽ ≈ 250 таких запросов; полный пакет подписки ≈ 3000. Цена и курс берутся с сервера. Это не обещание фиксированного числа генераций: картинки и текст расходуют один денежный остаток, резервы исключаются, дневные лимиты действуют отдельно. Неизвестный тариф показывает прочерк.

В чате и студии остаток обновляется после завершения/ошибки генерации, при фокусе и каждые 10 секунд на видимой странице; экран баланса обновляется при открытии, фокусе и каждые 10 секунд. Пока `BILLING_ENABLED=false`, показано отключение списаний.
