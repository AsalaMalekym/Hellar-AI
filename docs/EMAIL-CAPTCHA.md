# Почта и капча Hellar AI

## Поведение

- При каждом открытии/перезагрузке интерфейса посетитель проходит Turnstile. Внутренняя навигация не вызывает новую проверку. Серверный допуск действует 30 минут, привязан к браузеру через HttpOnly cookie и User-Agent; интерфейс предлагает повторную проверку через 29 минут. Аккаунтная сессия при этом не удаляется.
- Регистрация: имя, почта, приглашение и отдельная капча → письмо → пользователь задаёт пароль по ссылке → подтверждённый аккаунт. До последнего шага нет ни пользователя, ни сессии. Приглашение расходуется транзакционно только на последнем шаге; отзыв/истечение приглашения проверяются снова.
- Ссылка регистрации действует 30 минут и используется один раз. Если письмо не пришло, можно повторить регистрацию с тем же приглашением: максимум три письма на адрес в час. В базе хранятся хеши токенов. Пароль не принимается заранее, чтобы посторонний не мог задать его владельцу почты.
- Восстановление: почта и капча → одноразовая ссылка на 30 минут → новый пароль; все прежние сессии и ссылки восстановления аннулируются. Ответ на запрос одинаков для существующих и неизвестных адресов.
- Существующие аккаунты, включая владельца, сохраняют доступ. Первоначальная настройка владельца остаётся отдельной операцией с секретом SETUP_TOKEN. Подтверждение почты обязательно для **новых обычных регистраций**.
- Капча проверяется сервером, включая hostname и action. Сервер хранит использованные токены, чтобы блокировать конкурентное повторное применение. Прямые обращения к защищённому API без допуска не работают. Без настроенных ключей production закрыт, без почты регистрация и восстановление недоступны.

## 1. Отправитель Resend

1. Откройте https://resend.com/domains и добавьте свой домен (например `hellarai.ru`).
2. В DNS этого домена добавьте **точно те записи**, которые показывает Resend, и дождитесь Verified. Не заменяйте существующие MX записи входящей почты: используйте предлагаемый Resend поддомен Return-Path. Можно выделить поддомен для писем, но его тоже нужно подтвердить.
3. Отключите click/open tracking для писем авторизации. Приложение отправляет простой текст, ссылки содержат секрет во фрагменте `#`; отслеживание ссылок не требуется.
4. В https://resend.com/api-keys создайте ключ с правом Sending access для этого домена.
5. Отправитель: `Hellar AI <no-reply@hellarai.ru>` (или адрес на фактически подтверждённом домене). Отдельный входящий ящик для отправки этих писем не нужен.

Доставка и доступность сервиса зависят от аккаунта и DNS. Условия/лимиты проверяются в сервисе; код не активирует платный тариф. Тестовый `onboarding@resend.dev` не подходит для регистрации произвольных пользователей.

## 2. Cloudflare Turnstile

1. Cloudflare → Turnstile → Add widget, имя Hellar AI.
2. Выберите Rest of World и Managed. Добавьте hostname рабочего сайта: `hellarai.ru`, если он уже подключён; для технического адреса — `hellar-ai-cosmic.woen2017.workers.dev`. Только имена без `https://` и пути. Если используются оба адреса, добавьте оба; APP_ORIGIN приложения всё равно один.
3. Сохраните Site key и Secret key. Pre-clearance не нужен: приложение использует собственный серверный допуск. Не используйте демонстрационные ключи в production.

## 3. GitHub Secrets и публикация

https://github.com/AsalaMalekym/Hellar-AI/settings/secrets/actions → New repository secret:

| Имя | Значение |
| --- | --- |
| `RESEND_API_KEY` | Ключ отправки Resend |
| `MAIL_FROM` | Например `Hellar AI <no-reply@hellarai.ru>` |
| `TURNSTILE_SITE_KEY` | Site key |
| `TURNSTILE_SECRET_KEY` | Secret key |

Значения не отправляйте в чат и не добавляйте в исходники. Workflow передаёт их в секреты Worker; в браузер попадает только публичный Site key. Существующие CLOUDFLARE_ACCOUNT_ID/API_TOKEN сохраняются.

Убедитесь, что `HELLAR_APP_ORIGIN` (GitHub Variables) совпадает с рабочим адресом сайта: ссылки в письмах строятся из него. Например `https://hellarai.ru` — только если домен уже подключён к Worker. Публикация не меняет DNS/домен сайта автоматически.

Запустите **новый** Actions → Deploy Hellar to Cloudflare → Run workflow → main. Re-run прежнего запуска использует старую версию кода. Проверка наличия настроек выполняется до деплоя, чтобы не закрыть работающий сайт из-за отсутствующих ключей.

## Проверка после публикации

1. Откройте сайт заново: появится капча, после неё работает вход владельца.
2. Создайте приглашение и зарегистрируйтесь на свою вторую почту. До подтверждения вход невозможен. Откройте письмо, задайте пароль и войдите.
3. Повторное применение этой ссылки должно отклоняться. Проверьте восстановление пароля и завершение прежнего сеанса.
4. Если письма нет, проверьте Spam и журнал отправок Resend. Если капча не проходит, проверьте hostname виджета, его ключи и APP_ORIGIN. Не публикуйте токены ссылок или содержимое секретов.

Автотесты используют имитации Resend/Turnstile и не подтверждают доставку реальных писем, DNS или прохождение настоящего виджета. В этой среде интерактивная проверка браузера не выполнялась.
